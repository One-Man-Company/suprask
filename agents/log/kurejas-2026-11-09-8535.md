### 2. Kas pakeista

`assets/css/main.css`

- `.sim-controls` — `container-type: inline-size; width: 100%`.
- `@container (max-width: 16rem) { .sim-controls .btn { padding-inline: min(1.4rem, 3.5cqw);
  max-width: 100%; overflow-wrap: anywhere } }`. `rem` konteinerio užklausoje seka šaknies
  šriftą: 16 px šaknyje riba 256 px (juosta 298 px → sąlyga neaktyvi), 32 px šaknyje —
  512 px (juosta 241 px → aktyvi). 3,5 cqw = 8,4 px prie 241 px; tekstui lieka 224,1 px,
  ilgiausias žodis 222,5 px telpa; šriftas NEMAŽINTAS.
- `.sim-ask { max-width: 100% }`, `.sim-ask input { width: 8.5rem; max-width: 100%; min-width: 0 }`
  (laukas buvo 272 px prie 241 px juostos; laukas yra valdiklis, jo turinys slenkasi viduje).

`assets/js/sims/daile.js`, `assets/js/sims/muzika.js` — tos pačios klasės ir to paties
vaiko matomo defekto šaltiniai, kurių CSS vien neįveikia (`min-width` laimi prieš
`max-width`): `min-width:11rem` (352 px) → `min(11rem,100%)` ir `min-width:8rem` (256 px)
→ `min(8rem,100%)`. Abiem atvejais komentaras su matavimu. 16 px šaknyje `100 %` juostos
(298 px) didesnis už abu `rem`, tad plotis nepakinta.

## Klaidinga nuostata / Švietimo #1 sąsaja

Turinio nekeista. Platformos lygmenyje tai **T5.5 prieinamumas** ir gairių §6 techninė
patikra (WCAG 1.4.4 „resize text“ ir 1.4.10 „reflow“): vaikas, padidinęs tekstą iki 200 %,
turi matyti valdiklį savo kortelėje — su ta pačia etikete ir didesniu šriftu, o ne
išlindusį už kortelės krašto ar sumažintą, kad tik tilptų. Pasirinkimas sąmoningas:
paminkštinimą mažiname, **šrifto — ne** (LL-51, LL-70, #5842), o žodis laužomas tik tada,
kai fiziškai netelpa (tada įprastas kelias — žodžio pertrūkis, ne horizontalus slinkimas).
